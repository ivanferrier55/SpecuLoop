# 2026-08-25: Initial Research

## GraphRAG (Microsoft)

- **What it does**: Builds knowledge graphs from documents, uses community detection for retrieval
- **Problem it solves**: Graph-based retrieval from large document sets
- **What SpecuLoop shares**: Graph-based retrieval, entity-relationship model
- **What differs**: GraphRAG rebuilds graphs per query; SpecuLoop persists and incrementally updates. GraphRAG uses community detection; SpecuLoop uses lens-dependent scoring.
- **What we might learn**: Community detection could complement lens-based compression
- **Should we adopt**: Possibly — community detection as an additional compression strategy

## MemGPT / Letta

- **What it does**: Persistent memory for LLM agents using tiered text storage
- **Problem it solves**: Agent memory across sessions
- **What SpecuLoop shares**: Persistent memory, agent context management
- **What differs**: MemGPT uses flat text summaries; SpecuLoop uses semantic graphs with forces
- **What we might learn**: Tiered memory management strategies
- **Should we adopt**: The tiered approach could apply to graph depth

## RAPTOR

- **What it does**: Hierarchical retrieval with tree-based summarization
- **Problem it solves**: Multi-level retrieval from document sets
- **What SpecuLoop shares**: Hierarchical/multi-level retrieval
- **What differs**: RAPTOR uses fixed document trees; SpecuLoop uses dynamic graph compression
- **What we might learn**: Tree-based summarization could complement graph coarsening
- **Should we adopt**: Possibly — as an alternative coarsening strategy
